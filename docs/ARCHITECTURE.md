# بررسی مخزن و برنامه

مبنای مخزن فقط یک README با عنوان بود؛ افزونه، AGENTS.md، manifest، lockfile، CI یا استاندارد موجودی نداشت. بنابراین افزونهٔ موازی ساخته نشد و افزونهٔ جدید در ریشه ایجاد شد. نسخه‌های PHP 8.1+، وردپرس 6.5+ و ووکامرس 9+ فرض طراحی‌اند، نه ماتریس سازگاری تأییدشده.

## معماری و فایل‌ها

- `fa-wp-speedup.php`: bootstrap، چرخهٔ فعال/غیرفعال‌سازی و جلوگیری از فعال‌سازی شبکه‌ای.
- `includes/class-faws-catalog.php`: نگاشت immutable URL/نسخه/مجوز/SRI و اعتبارسنجی محتوا؛ افزودن منبع یک تغییر کد نیازمند بازبینی امنیتی است.
- `includes/class-faws-local.php`: دریافت محدود، consent، قفل، cooldown، نصب اتمیک، صحت فایل و حذف کنترل‌شده.
- `includes/class-faws-plugin.php`: مشاهدهٔ enqueue/HTML، تشخیص درخواست‌های خارجی، زمینهٔ صفحه، استثناهای فروشگاه و UI/فرم‌های دارای مجوز.
- `uninstall.php`: پاک‌سازی اختیاری فقط برای سایت جاری و فقط فایل‌های دقیق کاتالوگ.
- `licenses/`: مجوزهای Bootstrap و Popper همراه با فایل‌های دانلودی ارائه می‌شوند.
- `dev/` و `tests/`: سایت Docker دورریختنی، تست مرزی، یکپارچه، HTTP و مرورگر؛ وابستگی توسعه وارد افزونهٔ نصب‌شدنی نمی‌شود.

تنظیمات در optionهای اختصاصی غیرautoload نگهداری می‌شوند. هیچ جدول سفارشی، REST endpoint، تغییر SQL سفارش‌ها، کش صفحه یا فرایند minify وجود ندارد. مقادیر غیرقابل اعتماد در HTML escape می‌شوند. فرم‌ها فقط POST، nonce و `manage_options` دارند. SQL تشخیصی فقط aggregate روی جدول options با نام جدول مورد اعتماد وردپرس است و ورودی SQL از کاربر ندارد.

## قابلیت‌های این مرحله

تشخیص بدون تغییر رفتار، مشاهدهٔ CSS/JS محلی و خارجی، ثبت زمینه، منابع HTML، شمارش query و زمان اختیاری آن با SAVEQUERIES موجود، شمارش/زمان درخواست خارجی از pre_http_request تا http_api_debug، زمان PHP و حافظه، autoload، transient، object-cache، WP_CACHE، تعداد/قدیمی‌ترین cron و hookهای پرتکرار، شمارش pending/failed در Action Scheduler از API رسمی. هیچ فراخوانی profiler نمی‌تواند ترافیک خارج از HTTP API وردپرس را پوشش دهد.

جایگزینی فقط برای دو فایل Bootstrap نسخهٔ ثابت با دو مرحلهٔ رضایت، دریافت زمان‌بندی‌شده، گزارش و بازگشت؛ هیچ نتیجه‌ای از نام دامنه دربارهٔ کندی استنتاج نمی‌شود. زمان دریافت از سرور، اندازه‌گیری شبکهٔ بازدیدکننده نیست. آستانهٔ ۱۵۰۰ میلی‌ثانیه صرفاً علامت تشخیصی برای همان نمونه است؛ یک نمونه علت قطعی کندی محسوب نمی‌شود.

## تغییر مرحلهٔ دوم (۰٫۲)

`class-faws-media.php` و `class-faws-advanced.php` به معماری اضافه شدند. جزئیات قرارداد پردازش تصویر، قواعد صفحه، محافظت وابستگی، تشخیص تداخل، پاک‌سازی و پیش‌نمایش در [راهنمای مرحلهٔ دوم](IMAGES-ADVANCED.md) ثبت شده است. اسکریپت محلی `assets/media-audit.js` فقط در گزارش اختیاری مدیر فعال می‌شود.

## موارد باقی‌مانده پس از مرحلهٔ دوم

- async، delayed execution و ترکیب فایل‌ها ارائه نمی‌شوند؛ قواعد unload/defer موجود نیز برای تولید به baseline و تست قالب واقعی نیاز دارند.
- تشخیص خودکار LCP، سرو عمومی AVIF با picture/fallback در تمام گالری‌ها، تغییر گستردهٔ lazy-load و پشتیبانی HTML/CSS هاردکد باقی مانده‌اند. گزارش ابعاد و تولید مشتق‌های موجود جایگزین آن‌ها نیست.
- نمونه‌برداری کندی query و attribution به افزونه/قالب، cold/warm cache hit/miss معتبر و تعداد/حجم واقعی فونت و تصویر در گزارش محصول.
- قدیمی‌ترین/پرتکرارترین Action Scheduler، عملیات batch، retry و راهنمای cron میزبان؛ عملیات مخرب اکنون وجود ندارد.
- شبکهٔ multisite، نگاشت فونت/RTL، مانیتورینگ مرورگر برای fallback هنگام خطای HTTP فایل محلی و آزمون افزونه‌های کش/فیلتر/جست‌وجو/پیامک/چندفروشندگی/صفحه‌ساز.
- تست قالب فروشگاهی سنگین، کاتالوگ بزرگ، شبکهٔ شبیه‌سازی‌شدهٔ ایران با چند پروفایل تأخیر، و درگاه ایرانی sandbox.

## معیار انتشار پایدار

دریافت end-to-end با DNS و TLS واقعی، آزمون بازبینی کد و WPCS، ماتریس نسخه‌های حداقل و جاری، مسیر خرید و درگاه sandbox، آزمون کش‌های منتخب و بررسی دستی RTL/ترجمه لازم است. API رسمی سفارش‌ها تنها مسیر کار با سفارش است. آزمایش فعلی HPOS، مجوز اعلام سازگاری با همهٔ افزونه‌ها و درگاه‌ها نیست. هیچ عملیات گسترده، مهاجرت مخرب یا تغییر فایل افزونهٔ دیگر انجام نشده است.
